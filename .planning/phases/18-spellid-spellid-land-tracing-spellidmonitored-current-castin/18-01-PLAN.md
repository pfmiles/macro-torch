Inside `function macroTorch.SpellTrace:register(name, config)`, in the `if config.land then` branch, immediately after the existing `macroTorch.setSpellTracing(spellId, name)` call (line 78), insert the whitelist maintenance block.

The logic (per D-01, D-03):

```
-- [NEW Phase 18 per D-01, D-03] Whitelist maintenance: auto-register
-- spells whose spellId should be monitored for dynamic correction.
-- monitorSpellId defaults to config.land (nil treated as false).
-- Uses nil-aware default: (x ~= nil) and x or default
-- preserves explicit false (per RESEARCH Pitfall 2).
local shouldMonitor
if config.monitorSpellId ~= nil then
    shouldMonitor = config.monitorSpellId
else
    shouldMonitor = config.land or false
end
if shouldMonitor and config.spellName then
    macroTorch._spellIdMonitored[config.spellName] = true
end
```

Key design choices (from RESEARCH):
- Use `if config.monitorSpellId ~= nil then ... else ... end` (explicit if/else) rather than the one-liner `(x ~= nil) and x or default` pattern, to match the codebase's existing verbose style seen in `spell_trace_core.lua:66-77` multi-branch if/else.
- Do NOT use `config.monitorSpellId or config.land or false` — this would swallow explicit `monitorSpellId = false` (Lua: `false or x` returns `x`).
- The whitelist write goes AFTER `setSpellTracing` to maintain logical order: first set up tracing (operational), then update whitelist (administrative).
- `config.monitorSpellId` defaults to `config.land` — so land=true auto-monitors, land=false does not.
- When `config.spellName` is nil (legacy config.spellId-only path), whitelist write is skipped (per D-05).
</action>

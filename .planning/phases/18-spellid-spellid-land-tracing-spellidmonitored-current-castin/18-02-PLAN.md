With the Phase 18 whitelist-guarded version with stale detection (per D-02, D-04):

```
        if mode ~= 'ready' then
            -- [NEW Phase 18 per D-04] Stale detection: warn if previous value was not cleared
            -- by UNIT_CASTEVENT. This indicates SuperWow event loss or a bug in event handling.
            if macroTorch.current_casting_spell ~= nil then
                macroTorch.log("[macro-torch] current_casting_spell was not cleared: " ..
                    tostring(macroTorch.current_casting_spell) ..
                    ", now overwritten by: " .. localeNames.en, 'yellow')
            end
            -- [NEW Phase 18 per D-02] Whitelist guard: only set for spells whose
            -- spellId needs dynamic correction monitoring (land-tracing spells with spellName).
            -- Spells not in the whitelist skip this entirely — no pollution, no stale risk.
            if macroTorch._spellIdMonitored and macroTorch._spellIdMonitored[localeNames.en] then
                macroTorch.current_casting_spell = localeNames.en
            end
        end
```

Key implementation details (from RESEARCH):
- `macroTorch._spellIdMonitored` nil-check before indexing: `and macroTorch._spellIdMonitored[localeNames.en]` ensures the guard degrades safely (never sets current_casting_spell) if the whitelist was not initialized. Lua short-circuit evaluation: if `macroTorch._spellIdMonitored` is nil/false, the `[localeNames.en]` lookup is skipped entirely.
- `macroTorch.log(message, 'yellow')` for stale detection — uses the verified `(a, color)` signature from `interface_debug.lua:103`, NOT `(level, message)`. Yellow color warns without alarming.
- Use `tostring()` on `current_casting_spell` in the warning message to handle any non-string type that might have leaked in.
- The stale detection runs BEFORE the whitelist guard, so even if the current spell is NOT in the whitelist, you still get a warning if `current_casting_spell` was left dirty by a previous cast.
- The whitelist guard replaces the unconditional `macroTorch.current_casting_spell = localeNames.en` — if the spell is not in the whitelist, `current_casting_spell` is NEVER set (neither to the new spell name nor left stale).
- Events.lua (UNIT_CASTEVENT handler) requires ZERO changes: the existing `if macroTorch.current_casting_spell then` gate at line 98 naturally only triggers for whitelisted spells since that is the only time current_casting_spell gets set.

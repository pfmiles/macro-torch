## Summary

Reviewed the combined source diff `git diff dc6bc00..HEAD -- classes/druid/cat.lua core/selftest.lua`
(commits ad093c9 and 96e55d1, review targets per quick tasks 260825-s3v and 260825-t86). The changes
give `macroTorch.energyDischargeBeforeBite` a total boolean return contract and make `cp5Bite` defer
its bite verdict for one frame whenever a discharge attempt was initiated, plus a mirroring selftest.

**Design invariants — verdict per item:**

1. **Boolean contract is total — PASS.** All five return paths of `energyDischargeBeforeBite`
   (classes/druid/cat.lua:158, 163, 172, 181, 186) yield an explicit boolean. No `return` without a
   value, so a nil-return fall-through into the bite is impossible.
2. **No deadlock — PASS.** Non-OoC 5CP frames in the 35-69 window (and 70-79 when Rake is already
   present) match no discharge condition, hit the `return false` tail (line 186) and fall through to
   `safeBite`/`readyBite` at lines 145-149. `isPseudoInfiniteEnergy` frames skip the discharge block
   entirely via `shouldDischarge = false` and reach the tail verdict. Deferral is per-keystroke
   (user-driven), so no liveness problem.
3. **shouldDischarge=false branches undisturbed — PASS.** The isPseudoInfiniteEnergy and
   ripLeft <= 2.3 guards (lines 125-132) are untouched by both commits; those frames still bite
   directly.
4. **isDischarged frame-scoping — PASS.** `clickContext` is a fresh table rebuilt every keystroke
   (classes/druid/combo.lua:55); `isDischarged` is read/written only in cat.lua (lines 158/172/181)
   and appears nowhere else in the codebase. No module-level state leakage.
5. **regularAttack callers — PASS.** Unchanged; all 7 call sites discard its return as before.
   **quickKeepRip — PARTIAL (see WR-01):** the isDischarged dedup can never suppress a discharge
   quickKeepRip actually needs (the only prior setter in a frame is cp5Bite, whose conditions —
   isImmuneRip/isRipPresent/isFastBattleNotPvp at 5CP — are mutually exclusive with quickKeepRip's
   `not isRipPresent and not isImmuneRip` under `not isFastBattleNotPvp`), but discarding the
   boolean leaves the OoC bypass hole open on the quickKeepRip path itself.
6. **Selftest — PASS with a coverage note (see IN-01).** P-06 (core/selftest.lua:783-815) is
   semantically untouched: its ctx has `isPseudoInfiniteEnergy = true`, so the discharge block is
   skipped and the bite still fires. The new test (820-852) stubs `energyDischargeBeforeBite` to
   return true with `isPseudoInfiniteEnergy = false`, correctly asserting that `cp5Bite` returns
   without calling bite. It registers in Category P; the count comment (line 854) says 7, which
   matches the actual 7 registered `P:` tests.

The core t86 contract is correctly implemented; no blockers. One warning and two info items follow.

## Warnings

### WR-01: quickKeepRip discards the new boolean return, keeping the OoC discharge-bypass hole open on its own bite path

**File:** `classes/druid/cat.lua:337-338`
**Issue:** `quickKeepRip` calls `macroTorch.energyDischargeBeforeBite(clickContext)` and ignores the
return, then immediately calls `macroTorch.safeBite(clickContext)`. On an OoC frame in a trivial/PvP
battle with cp >= 3 and no Rip present, the discharge branch takes `regularAttack` in 'ready' mode —
the exact cast style that the game can silently reject (behind-verdict flip / GCD boundary, per the
domain background). When that happens the OoC proc is not consumed, `isDischarged` is still set (and
true is returned), but the discarded return means the function's own contract — "true means the bite
verdict must be re-sampled next frame" — is not honored here: `safeBite` runs in the same frame and
`readyBite` fires with the OoC proc still up, i.e. a free bite that converts all current energy at
bite's worse conversion rate. This is the same bug class the two quick tasks closed in `cp5Bite`
(was free-OoC-bite; and holes A/B for non-OoC), still reachable through this second caller.

Reachability: `quickKeepRip` runs only in `isTrivialBattleOrPvp` (not fast) battles with
`cp >= 3 and not isRipPresent and not isImmuneRip`; in that same frame `oocMod`/`termMod` cannot
have invoked `cp5Bite` (its gate requires immune/ripPresent/fast at 5CP), so a prior successful
discharge is impossible and the OoC state sampled at frame start persists. The pre-existing
`energyDischargeBeforeBite` discharge itself still runs — this is about the bite side, not the
discharge side. Not a data-loss/crash-level defect, but it degrades the fix's completeness.

**Fix:** honor the return contract in `quickKeepRip` exactly as `cp5Bite` now does (one line):

```lua
    if clickContext.comboPoints >= 3 and not macroTorch.isRipPresent(clickContext) and not clickContext.isImmuneRip then
        if macroTorch.energyDischargeBeforeBite(clickContext) then
            return  -- discharge attempted: re-sample the bite verdict next click
        end
        macroTorch.safeBite(clickContext)
        return
    end
```

(The next-click verdict naturally falls through `termMod`/`cp5Bite`, which now defers correctly.)

## Info

### IN-01: Selftest never exercises the `return false` tail with `shouldDischarge == true` (the no-condition-matched fall-through the fix relies on for liveness)

**File:** `core/selftest.lua:820-852`
**Issue:** P-06 leaves the discharge block via `isPseudoInfiniteEnergy = true` (shouldDischarge
becomes false before the block), and the new t86 test stubs `energyDischargeBeforeBite` to always
return true. Neither test runs `cp5Bite` with `shouldDischarge == true` and a real
`energyDischargeBeforeBite` that returns false (e.g. non-OoC, energy 35-79 with Rake present), so
the invariant-2 guarantee — "false return must still reach safeBite" — has no coverage. A future
regression that made the false tail accidentally defer or skip the bite would pass the suite
silently.

**Fix:** add a third P-category test mirroring P-06 with `isPseudoInfiniteEnergy = false`, an
unstubbed `energyDischargeBeforeBite`, a clickContext where no discharge condition matches
(e.g. `ooc = false, isBehind = false`, mana below `BITE_E + CLAW_E`, `isRakePresent` stubbed true,
`ripLeft` stubbed > 2.3), and assert `biteCalled == true`.

### IN-02: Duplicate isPseudoInfiniteEnergy filter inside energyDischargeBeforeBite is dead for its primary caller

**File:** `classes/druid/cat.lua:163-165` (vs. `classes/druid/cat.lua:125-127`)
**Issue:** `cp5Bite` only calls `energyDischargeBeforeBite` when `shouldDischarge` is true, which
already implies `not clickContext.isPseudoInfiniteEnergy`; the inner check at lines 163-165 can only
be reached from the `quickKeepRip` call site. This pre-dates the diff (only the return value
changed), but the divergence between the two filters is now a maintainability trap: adding another
discharge caller that forgets that fence implicitly relies on the hidden inner check.

**Fix:** either drop the inner check and rely on callers' fences, or keep it but comment that it is
the single defensive guard for callers without their own fence (currently only quickKeepRip).

## Warnings

### WR-01: `--erps` 校验放过 inf/nan → `--json-out` 产出非法 JSON（违背锁定约束 4）

**File:** `tools/cpdamage.lua:1524`（`main` FLAG_ERPS 分支：`if num == nil or num < 0 then`）

**Issue:** 校验只拒 `nil` 与负数，非有限数（inf/nan）全部穿透。`inf < 0` 为 false，`nan < 0` 为 false。实机取证（本机三解释器）：

- 5.0.3 / 5.1.5：`tonumber('inf')`、`tonumber('nan')` 均返回真值；三个解释器 `tonumber('1e999')` 全返回 `inf`（5.4.7 也不例外）。
- `--erps inf`（5.0.3）→ exit 0，屏显 `assumed ERPS = inf/s`，JSON 文件写入 `"erps":inf`（`encodeScalar` 路径：`inf == math.floor(inf)` 为真 → `'%.0f'` → 裸 `inf` token）；Node `JSON.parse` 实测报 `Unexpected token 'i', ..."erps":inf}...`。
- `--erps nan`（5.0.3）→ exit 0，写入 `"erps":nan`，同样非法。
- `--erps 1e999`（5.4.7，最严格解释器）→ exit 0，写入 `"erps":inf`，Node parse 失败。

即任务锁定约束 4（"Node `JSON.parse` 可解析"）可被一行命令打破，且受影响的是**全部三个目标解释器**，不是仅 legacy。nan 情形下 verdict 全静默落 D、屏显 `nan/s`，无任何告警。

**Fix:**
```lua
elseif a == FLAG_ERPS then
    local num = tonumber(args[i + 1])
    -- Lua 5.0 has no math.huge: nan check via self-inequality,
    -- inf excluded by a sane ERPS ceiling (CRITERIA doc: 10/s base,
    -- 狂暴 +50/s ceiling - 999 is far above any reachable value)
    if num == nil or num < 0 or num ~= num or num > 999 then
        io.write('error: ' .. FLAG_ERPS ..
            ' requires a non-negative energy-per-second number\n')
        printUsage()
        os.exit(1)
    end
    erps = num
    i = i + 2
```

### WR-02: rDB 构造分支对 `avgEff`/`avgDmg` 无 nil 守卫，与同函数 E 循环的守卫不对称

**File:** `tools/cpdamage.lua:1093-1096`

**Issue:** E 循环（1071-1072 行）显式守卫 `b.n > 0 and b.avgEff ~= nil`——作者自身的防御模型已承认 `n>0` 时 `avgEff` 可能为 nil；而 rDB 分支只查 `cb ~= nil and cb.n > 0`，随后直接 `(cb.avgDmg - 37 * reg.b) / cb.avgEff`。若传入形如 selftest 手写 `ctrlStats` 这类 stats（`{ n = 20, avgDmg = nil }`），该行抛 `attempt to perform arithmetic on a nil value` 硬崩溃，而不是像本函数其余分支那样优雅降级（no bleed2 shred samples / no bleed<N> claw samples / note）。真实管线（`buildClawShredBuckets.finalize`）保证 `n>0 ⇒ avgDmg/avgEff 非 nil`，故当前主链不可达；但 `oocBiteCriteria` 是公开纯函数，selftest 已示范手写 stats 入参用法，守卫不对称是潜伏雷。

**Fix:**
```lua
if cb ~= nil and cb.n > 0 and cb.avgDmg ~= nil and cb.avgEff ~= nil then
    rDB[tierKeys[ti]] = { C = cb.avgDmg, E = cb.avgEff,
        r = (cb.avgDmg - 37 * reg.b) / cb.avgEff }
    anyTier = true
end
```

### IN-01: `oocBiteCriteria` 兜底 erps 用字面量 `10` 而非 `DEFAULT_ERPS`

**File:** `tools/cpdamage.lua:1048`（对照第 40 行 `DEFAULT_ERPS = 10`）

**Issue:** `local crit = { erps = tonumber(erps) or 10 }` 硬编码 10。若将来改 `DEFAULT_ERPS`（如按 CRITERIA 文档校准流程调整缺省回能），函数兜底与 CLI 缺省将静默分叉。虽 PLAN 锁定行逐字如此（非执行偏差），仍属维护隐患。**Fix:** `tonumber(erps) or DEFAULT_ERPS`。

### IN-02: 函数层 erps 契约与 CLI 校验不一致（负数静默接受）

**File:** `tools/cpdamage.lua:1048, 1112-1118`

**Issue:** CLI 明确拒绝负 erps，但 `oocBiteCriteria` 自身对负数仅产生"全 D verdict + 负值回显（`-3/s`）"的静默结果，无任何拒绝或 clamp；非 numeric 入参则静默吞掉并兜底 10。函数是公开入口（selftest 直接调用），契约比 CLI 宽松且无文档化。**Fix:** 在函数头对 `erps` 做与 CLI 同等的 `nil/负/非有限` 归一化（归一失败兜底 DEFAULT_ERPS），或至少在注释中声明"调用方负责非负有限"。

### IN-03: 空 `verdicts` 表在 JSON 中序列化为数组 `[]` 而非对象 `{}`

**File:** `tools/cpdamage.lua:1104-1122`（`crit.verdicts = verdicts`，空表分支）

**Issue:** 当 rAB 存在但 rDB 两层全缺时（可达真实数据：claw 样本只落在 tier 0/1、shred[2] 有样本），`verdicts = {}` 空表经 `encodeValue` 的空表启发式（`numericCount == total == nMax == 0`）输出 `"verdicts":[]`；而非空时输出 `"verdicts":{"bleed2":"A","bleed3":"A"}`。JS 下 `d.oocBite.verdicts.bleed2` 均为 undefined 无功能差异，但严格类型消费者会看到 Array/Object 形变；屏显该场景两个 `n/a` 正常。建议空表时保持 nil（不写 verdicts 键）或文档化该形变。

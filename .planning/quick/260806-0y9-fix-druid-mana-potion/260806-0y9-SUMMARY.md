# Quick Task 260806-0y9 Summary

**Date:** 2026-08-06
**Status:** complete

## Problem

In cat/bear form, `UnitMana("player")` returns energy/rage instead of real caster mana, causing `shouldUseManaPotion()` to always trigger (threshold comparison against form power is meaningless), wasting mana potions.

SuperWoW extends `UnitMana`/`UnitManaMax` for druids to return `(formPower, casterMana)` — the second return value is the real mana independent of form. The original code only used the first return value.

## Changes

All changes in `classes/druid/Druid.lua`:

1. **`humanFormMana`** — When SuperWoW is present AND in cat/bear form, extracts the second return value of `UnitMana` (real caster mana). Falls back to standard `UnitMana` otherwise.

2. **`humanFormManaMax` (new property)** — Symmetric logic using `UnitManaMax` second return value, providing a form-independent max mana reading.

3. **`getManaPotionThreshold()`** — Switched from `UnitManaMax('player') * 0.3` to `macroTorch.player.humanFormManaMax * 0.3`, so the threshold is computed from real max mana.

4. **`shouldUseManaPotion()`** — When SuperWoW is NOT installed AND in cat/bear form, returns `false` immediately to disable auto potion use. Without SuperWoW's extended API, the mana reading is unreliable so the safe choice is to not consume potions.

## Design Matrix

| Scenario | humanFormMana returns | humanFormManaMax returns | shouldUseManaPotion |
|---|---|---|---|
| No SuperWoW, cat/bear | energy/rage (no change) | max energy/rage | **false (disabled)** |
| No SuperWoW, caster | real mana (no change) | real max mana | threshold vs real mana |
| SuperWoW, cat/bear | real caster mana (second retval) | real max caster mana | threshold vs real mana |
| SuperWoW, caster | real mana (fallback) | real max mana (fallback) | threshold vs real mana |

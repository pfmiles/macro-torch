<objective>
Add a callable `macroTorch.target.clear()` method on the target object that
wipes ALL persisted immune and definite-bleeding tracking records for the
currently targeted mob — the two mob-name-keyed tables the addon keeps in
SM_EXTEND (immuneTable and definiteBleedingTable, per-player-class sub-tables
bound to macroTorch.context by the lazy loaders in core/spell_trace_immune.lua).
When invoked from a SuperMacro macro body, it clears the current target's
memory so the tracing system treats that mob as freshly seen. With no current
target (name nil) or an empty name, it silently does nothing — no chat output,
no table mutation.

Purpose: give the player an instant in-game escape hatch from stale
immune/definite records (a mob previously sniffed as immune / definite-bleeding
stays marked forever across sessions until now; clear() resets exactly that
mob on demand).

Output: `entity/Target.lua` gains one method `obj.clear()` inside
`macroTorch.Target:new()`; `core/selftest.lua` gains a light Category R pair of
selftests (R-01 wipe + unrelated-mob survival + single aggregate message, R-02
silent skip on empty target name). No other behavior changes. SM_Extend.lua is
NOT rebuilt (established convention: the build artifact is only regenerated on
an explicit project rebuild; recent quick tasks did not touch it).
</objective>

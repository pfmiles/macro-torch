# 木桩簇判别：Rake 蓝(inferred) 与二次补耙

## 已推演的主链条（Path A，环境链，非回归）

1. bite 落地后 FB 续期只召唤了 Rip 分支：客户端 hasBuff(Rake) 此时读到假（debuff 数据滞后，M3 签名）。
2. 宏判定 Rake 缺席 → Reshift nextMove: Rake → 补耙 A。
3. 补耙 A 落在"服务器其实已被咬刷新的 Rake"上：同施法者刷新时服务器跳过 apply 行 → A 只剩自伤行一条证据通道；该自伤行又被咬/续期/换形事件洪流推迟超过 0.9s → 沉默窗反推兜底 → 蓝 (Inferred)（兜底正常工作）。
4. 兜底不改动 hasBuff，客户端数据仍滞后 → 宏再补耙 B → B 自伤行正常到达 → 绿；此后客户端 debuff 数据跟上 → 恢复。

## 双路径判别（固化为下次取证 todo）

| 判别点 | Path A（环境） | Path B（回归嫌疑） |
|--------|----------------|--------------------|
| 蓝行与绿行的 landed 时间戳差 | ≈3-4s（两发真耙：B 需能量回填+决策间隔） | 几乎同刻（同一发耙的自伤行在推断后迟到，且未被标记判别静默丢弃→绿） |
| 蓝行出现时目标 Rake 图标 | 图标在 → M3 客户端滞后坐实 | 图标不在 → 服务器刷新失效，需复查服务器路径（与用户先前裁决矛盾，概率低） |
| 绿行前是否有新白字 Rake!!! | 有（第二次施放打印）→ 两发真耙 | 无 → 同耙双报 |
